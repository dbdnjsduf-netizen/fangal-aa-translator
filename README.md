# Fangal AA Translator

일본어 아스키 아트(AA/Shift-JIS Art) 텍스트를 한국어로 번역하면서 그림과 대사 위치를
최대한 보존하는 로컬 웹 앱입니다. 실행 중 상단의 **번역 엔진** 메뉴에서 다음 네 모드를
선택할 수 있습니다.

- **Ollama**: 로그인한 Ollama의 `gemma4:31b-cloud` 구독 할당량 또는 로컬
  `translategemma:4b` 모델을 선택해 사용합니다.
- **Gemini API**: 사용자가 입력한 Google API 키로 `gemini-3.6-flash`,
  `gemini-3.1-flash-lite` 중 하나를 직접 호출합니다.
- **Codex 로그인**: Codex CLI에 ChatGPT 계정으로 로그인한 구독 할당량을 이용해
  `gpt-5.6-luna`로 번역합니다.
- **OpenRouter API**: 사용자가 입력한 OpenRouter 키로
  `google/gemma-3-27b-it`(Gemma 3 27B)를 호출합니다.

## 주요 기능

- 일본어 자연어와 AA 선·반복 기호를 분리하는 스마트 선택
- 말풍선 경계를 이용한 세로쓰기 복원과 실제 문자 슬롯만 표시
- 가로 텍스트를 박스로 지정하고 기존 세로 감지도 가로로 덮어쓰는 수동 선택
- 세로쓰기를 박스로 한 문장으로 묶고 기존 가로 감지도 세로로 덮어쓰는 세로수동 선택
- 반복되는 장식·오인식 원문을 한 번 클릭해 이후 파일의 전체 선택에서도 제외하는 금지 목록
- 좌우 공백 경계에서 저장한 원문과 완전히 같은 문자열만 다시 고르는 수동 정규식(한 글자는 상하좌우 표시 폭 2칸 여백 또는 엄격히 검증된 닫힌 상자 안에서 허용)
- 검증된 닫힌 박스·사방의 지역 여백·상하의 정렬된 정상 문장만 사용하는 보수적 자동 선택
- 일반 한 글자는 전체선택에서 제외하고, 수동정규식으로 명시했더라도 상하좌우 표시 폭 2칸이 비어 있을 때만 예외 처리
- 상단에서 즉시 전환하고 다음 실행에도 유지되는 AA 화이트 모드
- 세로 번역이 길어져도 일본어 원문을 남기지 않는 최소 확장 배치
- 엄격한 입력/출력 1:1 검증, 일본어 잔존 검사, 실패 청크 자동 분할 복구
- 일부 청크·세로 그룹 오류를 격리하고 정상 번역은 끝까지 적용하는 부분 완료 처리
- Ollama·OpenRouter 최대 3개, Gemini·Codex 최대 2개의 동적 병렬 워커
- 사용자 사전, 실제 적용 내용 확인·복사가 가능한 번역 프롬프트, 실행 중 엔진 전환
- Saitamaar 렌더링을 유지한 PNG/JPG 페이지 이미지 ZIP 내보내기

## 빠른 시작

### Windows 초보자용 실행 방법

이 프로그램은 로컬 번역기 서버를 실행하기 위해 **Node.js 20 이상**과 Node.js에
포함된 **npm**이 필요합니다. 새로 설치한다면 공식 사이트의 최신 **LTS** 버전을
권장합니다.

1. [Node.js 공식 다운로드 페이지](https://nodejs.org/en/download)를 엽니다.
2. **LTS** 버전의 **Windows Installer(.msi)**를 내려받습니다.
3. 설치 프로그램은 특별한 이유가 없다면 기본값 그대로 `Next`를 눌러 설치합니다.
   npm과 PATH 등록 항목도 기본값으로 유지합니다.
4. 설치가 끝나면 열려 있던 명령 프롬프트를 닫습니다.
5. GitHub의 **Code → Download ZIP**으로 프로젝트를 내려받고 압축을 풉니다.
6. 압축을 푼 폴더에서 `start.bat`를 더블클릭합니다.

`start.bat`는 Node.js와 npm 설치 여부 및 버전을 자동으로 검사합니다. Node.js가 없거나
너무 오래된 경우 한국어 해결 방법을 표시하고 공식 다운로드 페이지를 엽니다. 처음
실행할 때는 `npm install`도 자동으로 진행하므로 인터넷 연결이 필요합니다. 정상 실행
단계에서는 서버 콘솔을 숨기고 준비가 끝난 뒤 브라우저를 자동으로 엽니다. 마지막 번역기
탭을 닫으면 백그라운드 서버도 자동으로 종료됩니다. 새로고침이나 여러 탭 중 하나만 닫는
경우에는 서버를 유지합니다.

### 필요한 프로그램

- Node.js 20 이상 — 최신 LTS 권장
- npm — Node.js 공식 설치 프로그램에 포함
- Ollama 모드를 쓸 경우 Ollama 앱과 계정
- Gemini 모드를 쓸 경우 본인의 Gemini API 키
- Codex 모드를 쓸 경우 Codex CLI와 ChatGPT 로그인
- OpenRouter 모드를 쓸 경우 본인의 OpenRouter API 키

각 번역 엔진은 선택 사항입니다. 사용할 엔진 하나만 준비하면 됩니다.

### 명령어로 실행하는 방법

```bash
git clone https://github.com/dbdnjsduf-netizen/fangal-aa-translator.git
cd fangal-aa-translator
npm install
npm run dev
```

브라우저에서 `http://127.0.0.1:3000`을 엽니다. macOS/Linux에서는 `./start.sh`를
실행할 수 있으며, 이 스크립트도 Node.js와 npm을 먼저 검사합니다.

프로덕션 실행:

```bash
npm run build
npm start
```

## 번역 엔진 설정

### Ollama Pro 모드

가장 쉬운 방법은 로컬 Ollama 앱의 로그인 세션을 이용하는 것입니다.

```bash
ollama signin
ollama pull gemma4:31b-cloud

# 구독 할당량 없이 로컬 TranslateGemma 4B를 사용할 경우
ollama pull translategemma:4b
```

프로젝트 루트에서 `.env.example`을 `.env`로 복사한 뒤 기본값을 그대로 사용할 수
있습니다.

```dotenv
OLLAMA_HOST=http://127.0.0.1:11434
OLLAMA_MODEL=gemma4:31b-cloud
OLLAMA_MAX_CONCURRENCY=3
```

로컬 Ollama를 통하지 않고 Cloud API에 직접 연결하려면 본인의 키를 `.env`에만
설정합니다.

```dotenv
OLLAMA_HOST=https://ollama.com
OLLAMA_MODEL=gemma4:31b
OLLAMA_API_KEY=replace_with_your_own_key
```

`.env` 파일은 Git에서 제외됩니다. 브라우저에는 Ollama 인증 정보가 전달되지 않고
Node 서버 프록시가 요청을 중계합니다.

### Gemini API 모드

1. 앱 상단의 **번역 엔진** 버튼을 엽니다.
2. **Gemini API**를 선택합니다.
3. Google AI Studio에서 발급한 본인 키를 입력하고 적용합니다.

Gemini 키는 소스 코드나 `.env`에 넣지 않습니다. 현재 브라우저 탭의
`sessionStorage`에만 보관되며 탭 세션이 끝나면 제거됩니다. 요청은 브라우저에서
Google Gemini API로 직접 전송되고 앱 서버 로그에는 키가 기록되지 않습니다.

> 공개 배포본에 공용 Gemini 키를 내장하지 마세요. 이 모드는 각 사용자가 자신의 키를
> 직접 입력하는 BYOK(Bring Your Own Key) 방식입니다.

### Codex 로그인 모드

1. [Codex 인증 안내](https://learn.chatgpt.com/docs/auth)에 따라 Codex CLI를 설치합니다.
2. 터미널에서 `codex login`을 실행하고 ChatGPT 계정으로 로그인합니다.
3. `codex login status`에 `Logged in using ChatGPT`가 표시되는지 확인합니다.
4. 앱의 **번역 엔진 → Codex 로그인**에서 상태를 새로 확인하고 적용합니다.

모델은 `gpt-5.6-luna`로 고정됩니다. 앱은 `auth.json` 같은 OAuth 인증 파일을 직접
읽거나 저장하지 않으며, 임시 작업 폴더에서 읽기 전용·일회성 `codex exec`를 실행합니다.
ChatGPT 구독 사용 가능 여부와 한도는 로그인한 계정의 플랜에 따릅니다.

### OpenRouter API 모드

1. [OpenRouter API Keys](https://openrouter.ai/settings/keys)에서 본인의 키를 만듭니다.
2. 앱의 **번역 엔진 → OpenRouter API**에서 키를 입력하고 적용합니다.
3. 모델은 `google/gemma-3-27b-it`로 고정됩니다.

키는 Gemini 키와 마찬가지로 현재 탭의 `sessionStorage`에만 보관됩니다. 요청할 때
로컬 Node 서버가 OpenRouter로 중계하며 키를 환경파일이나 서버 로그에 기록하지 않습니다.

## 엔진별 처리 전략

네 모드는 같은 번역 규칙, 사전, 응답 파서와 검증기를 사용합니다.

| 항목 | Ollama | Gemini | Codex | OpenRouter |
|---|---:|---:|---:|---:|
| 선택 모델 | `gemma4:31b-cloud`, `translategemma:4b` | `gemini-3.6-flash`, `gemini-3.1-flash-lite` | `gpt-5.6-luna` | `google/gemma-3-27b-it` |
| 목표 청크 | 2,400자 / 50항목 | 2,800자 / 50항목 | 1,800자 / 36항목 | 2,200자 / 44항목 |
| 강제 상한 | 3,200자 / 64항목 | 3,600자 / 64항목 | 2,500자 / 48항목 | 3,000자 / 56항목 |
| 동시 워커 | 최대 3 | 최대 2 | 최대 2 | 최대 3 |

엔진별 목표 청크는 구조화 응답 안정성과 API·구독 쿼터 급증 방지를 위한 보수적
설정입니다. Codex는 CLI 실행 자체의 문맥 비용이 있어 36항목, OpenRouter Gemma는
44항목을 목표로 더 작게 나눕니다. 한 청크의 응답 항목 수가 맞지 않거나 원문이 남으면 같은 큰 요청을
무한 반복하지 않고 문맥 경계에 가까운 지점에서 둘로 나눠 재시도합니다. 최악의
경우 한 항목 단위까지 축소하므로 앞부분 전체가 누락되는 현상을 방지합니다. 이미
번역한 말 뒤에 원문을 덧붙인 `용사(勇者)` 같은 결과는 중복 원문만 안전하게 제거하고,
실제로 일본어가 남은 항목은 정상 항목을 다시 요청하지 않고 해당 항목만 격리 재번역합니다.
일부 청크나 세로 말풍선의 좌표 적용만 끝까지 실패하면 정상 결과는 그대로 반영하고 실패한
항목만 선택 상태로 남깁니다. 모든 청크가 실패한 연결·인증 장애에만 전체 실패를 표시합니다.

## 사용 방법

1. `.txt`, `.mlt`, `.ast` 파일을 열거나 빈 파일에 내용을 붙여넣습니다.
2. 스마트 모드에서 자동 표시된 일본어 대사를 확인합니다.
3. 빠진 가로 텍스트는 하단의 **수동**을 켜고 텍스트 전체를 주황색 박스로 드래그합니다. 박스 안에 중심점이 들어간 문자 범위만 추가됩니다.
4. 빠지거나 방향이 잘못 감지된 텍스트는 **수동**으로 가로 지정하거나 **세로수동**으로 세로 지정합니다. 여러 세로 열은 오른쪽 열부터 한 문장으로 묶입니다.
5. 어느 수동 모드에서든 기존 자동 감지 일반 대사나 세로쓰기 그룹을 살짝 클릭하면 선택을 끄거나 다시 켤 수 있습니다.
6. 앞으로도 자동 선택할 정확한 원문은 하단의 **수동정규식**을 켜고 텍스트를 박스로 드래그합니다. 저장한 문자열과 좌우 공백 경계가 완전히 같은 항목만 즉시 선택하며, 한 글자 규칙은 상하좌우가 표시 폭 2칸 이상 비어 있거나 위·아래 덮개와 좌우 벽이 모두 검증된 상자 안일 때 적용합니다. 비슷한 글자·반복 수·말끝 장식은 일반화하지 않습니다.
7. 기본 자동 선택은 **위·아래 덮개와 좌우 벽이 모두 검증된 박스**, **상하좌우에 충분한 지역 여백이 있는 독립 블록**, **바로 위나 아래의 정상 문장과 가로 위치가 이어지는 문장**만 허용합니다. 이 근거가 없는 AA 내부 일본어 모양 문자는 전체 선택에서 보류합니다.
8. 반복되는 장식이나 번역하면 안 되는 오인식은 먼저 **전체 선택**한 뒤, 하단의 **금지하기**를 켜고 해당 선택 항목을 클릭합니다. 완전히 같은 일반 원문 또는 세로쓰기 문장들이 함께 해제되고 다음 파일에서도 제외됩니다.
9. 실수로 금지한 항목은 상단의 **금지항목 관리**에서 삭제합니다. 두 목록 모두 브라우저에 보관되며 JSON으로 백업·복원할 수 있습니다.
10. 상단의 **화이트** 버튼으로 AA 뷰어와 유사한 밝은 작업 화면을 사용할 수 있습니다.
11. **일괄 번역**을 실행하고 결과를 확인한 뒤 다운로드합니다.

색상 의미:

- 파랑: 일반 자동 감지 대사
- 보라: 세로쓰기 그룹
- 주황: 사용자가 직접 추가한 문자 범위
- 자홍: 사용자가 박스로 묶은 세로쓰기 그룹
- 청록: 수동 정규식의 정확 일치로 자동 선택한 원문
- 빨강 취소선: 금지 목록에 의해 전체 선택에서 제외된 항목

| 변수 | 기본값 | 설명 |

| `OPENROUTER_MAX_CONCURRENCY` | `3` | OpenRouter 동시 요청 수, 1~3 |
| `APP_HOST` | `127.0.0.1` | 앱 서버 바인딩 주소 |
| `PORT` | `3000` | 앱 서버 포트 |
| `APP_AUTO_SHUTDOWN` | 로컬 주소에서 켜짐 | 마지막 앱 탭과 함께 서버 자동 종료. `0`/`false`로 비활성화 |
| `APP_SHUTDOWN_DELAY_MS` | `4000` | 마지막 앱 탭 종료 후 서버 종료까지의 재접속 유예 시간(1000~30000ms) |

## 보안

- 실제 `.env`, 개인 키 파일, 인증 JSON, 로그와 빌드 산출물은 `.gitignore`로 제외됩니다.
- 예제 설정에는 플레이스홀더만 있으며 실제 키가 포함되지 않습니다.
- 서버와 클라이언트는 API 키 값을 콘솔에 출력하지 않습니다.
- Codex OAuth 인증 캐시는 Codex CLI만 사용하며 앱 코드가 직접 읽거나 복사하지 않습니다.
- 번역할 파일 내용은 선택한 AI 제공자에게 전송되므로 민감한 문서는 각 제공자의
  데이터 처리 정책을 확인한 뒤 사용하세요.

## 문제 해결

- **Ollama 연결 실패**: Ollama 앱 실행, `ollama signin`, `OLLAMA_HOST`를 확인합니다.
- **Ollama 모델 없음**: 설정에서 선택한 모델명으로 `ollama pull <모델명>`을 실행합니다.
- **Gemini 401/403**: 입력한 키와 해당 Google 프로젝트의 Gemini API 권한을 확인합니다.
- **Codex 로그인 실패**: `codex login` 후 `codex login status`를 실행하고 앱에서 상태를 새로 확인합니다.
- **Codex 모델 오류**: Codex CLI를 업데이트하고 로그인 계정의 `gpt-5.6-luna` 사용 가능 여부를 확인합니다.
- **OpenRouter 401/402/403**: API 키, 크레딧 잔액과 `google/gemma-3-27b-it` 사용 권한을 확인합니다.
- **429 요청 한도**: 계정 쿼터를 확인하고 잠시 후 다시 시도합니다.
- **번역 항목 수 불일치**: 앱이 자동으로 청크를 분할해 복구합니다. 끝까지 실패한
  항목만 선택 상태로 남기며, 모든 청크가 실패한 경우에만 일괄 작업을 중단합니다.
- **일괄 번역 부분 완료**: 표시된 실패 항목만 선택 상태로 남습니다. 파일 전체를 다시
  선택하지 말고 남아 있는 항목만 재번역하면 이미 완료된 부분은 건드리지 않습니다.
- **세로쓰기 원문 슬롯 복구 실패**: 현재 버전은 앞선 번역의 길이 변화, 반각 문자,
  부분 결과 선반영은 자동 복구합니다. 번역 중 원문을 직접 편집·삭제한 경우에만 남을 수
  있으며, 오류에 표시된 말풍선을 **세로수동**으로 다시 묶은 뒤 재시도하면 됩니다.

## 프로그램 업데이트

상단의 버전 버튼을 누르면 현재 설치 버전과 GitHub `main`의 최신 버전을 다시 확인할 수
있습니다. 새 버전이 있으면 **설치**를 누르세요. 다운로드, 의존성 설치, 배포 빌드 검증,
파일 교체와 서버 재시작을 자동으로 처리합니다.

- ZIP으로 설치한 사용자도 자동 업데이트를 사용할 수 있습니다.
- `.env`, API 키와 브라우저에 저장된 사전·금지항목·수동정규식은 유지됩니다.
- Git으로 받은 폴더에 직접 수정한 파일이 있으면 자동 업데이트가 이를 덮어쓰지 않고
  중단됩니다. 변경을 별도로 백업하거나 커밋한 뒤 다시 실행하세요.
- 업데이트 도중에는 번역 작업을 시작하지 말고 완료 안내가 나올 때까지 창을 유지하세요.
- 인터넷 연결 또는 `npm install`에 실패하면 기존 파일로 되돌리고 오류 내용을 표시합니다.

### 1.11.11 (2026-08-11) — 게시물 문맥 번역과 자동선택 정밀화

- 약 50개 번역 항목 전후에 2ch 게시물 헤더가 있으면 그 위치를 청크 경계로 우선 사용합니다. 같은 게시물의 앞뒤 대사는 생략된 주어·지시어·말투와 용어를 판단하는 문맥으로 함께 읽습니다.
- 줄마다 출력 위치는 유지하면서도 여러 줄이 문법적으로 한 문장이면 관형절·연결절을 종결형으로 끊지 않습니다. `見た事ない`가 다음 줄의 명사를 꾸미는 경우 `본 적 없어`가 아닌 `본 적 없는`처럼 이어 번역합니다.
- 독립된 숫자+한자+문장부호, 영문 약어+한자, 하트 종결 대사와 점선 상태창처럼 실제 대사인 짧은 표현을 더 잘 선택합니다.
- 눈썹에 쓰이는 라틴 문자·작은 가나·반복 한자 혼합 조각은 주변의 여러 행이 밀집 AA일 때 그림으로 제외하고, 검증된 말풍선과 독립 대사는 보호합니다.
- 긴 수동정규식이 여러 자동선택 조각으로 나뉘어 있어도 전체 문자열을 먼저 한 덩어리로 복원해 내부의 짧은 규칙·금지 표시가 문장을 갈라놓지 않게 했습니다.

### 1.11.10 (2026-08-10) — 번역 프롬프트 전면 개편과 내용 확인

- 프롬프트 버튼을 누르면 실제 AI에 전달되는 출력 규칙·말투 규칙·사용자 스타일을 한 화면에서 확인하고 복사할 수 있습니다. 사용자 스타일 편집은 별도 탭에서 계속 지원합니다.
- 오래된 세로쓰기 글자 수 제한과 강제 띄어쓰기 생략 지시를 제거했습니다. 세로쓰기 배치 정보는 AI에 보내지 않고, 이미 읽기 순서로 복원된 온전한 문장만 번역합니다.
- 번역의 의미·경어·감정·반복·효과음 보존, 항목별 1:1 대응, 일본어 잔존 방지와 실패 항목 재시도 지시를 현재 처리 방식에 맞춰 전면 재작성했습니다.
- AA에서는 화자를 확실히 알기 어렵다는 점을 반영해 `だお·だろ·でしょ·ですぅ·かしら·にょろ` 등의 말투를 화자 추측이 아닌 현재 원문의 어미로 적용합니다. 해당 어미가 없는 다른 대사로는 말투를 번지게 하지 않습니다.
- 이전 기본 프롬프트는 새 기본값으로 자동 갱신하며 사용자가 직접 작성한 번역 스타일은 그대로 보존합니다.

### 1.11.9 (2026-08-10) — AA 캐릭터 고유 말투 보존

- 야루오의 `だお→~다오`, 야라나이오의 `だろ→~겠지`, 야라나이코의 `でしょ→~겠지?/~잖아?`처럼 원문 어미를 한국어 캐릭터 말투로 대응합니다.
- 데키루오의 경어, 스이세이세키의 `ですぅ`, 카나리아의 `かしら`, 뎃테이우의 `っていうｗ`, 츠루야상·츄루야상의 `にょろ/にょろーん`도 각 말투로 보존합니다.
- 고유 어미가 원문에 실제로 있는 항목에만 대응을 적용합니다. 흔한 `だろ·でしょ·경어`는 문맥에서 해당 캐릭터가 확인될 때만 사용하며 다른 화자나 평범한 문장으로 말투를 퍼뜨리지 않습니다.

### 1.11.8 (2026-08-10) — 짧은 말풍선 대사와 캐릭터 말투 보강

- 닫힌 말풍선 안의 `体ねーー`, `君は`처럼 짧은 한자·가나·장음·조사 조합도 전체 선택하고 상자 밖 AA 조각은 계속 제외합니다.
- `きりにょーん`처럼 중간에 장음표가 들어간 가나 효과음과 `皇帝よ？　皇帝`처럼 전각 공백으로 이어진 우측 독립 문장을 한 덩어리로 선택합니다.
- 상자 안의 단일 한자를 수동정규식으로 지정하면 상자 테두리를 장애물로 오인하지 않고 선택하며, 닫히지 않은 가짜 상자는 허용하지 않습니다.
- 원문에 야루오 특유의 `だお`, `だおね`, `だおよ` 또는 종결 `お`가 실제로 있을 때만 `~다오` 계열 말투를 보존합니다.

### 1.11.7 (2026-08-09) — 독립 대사·상태창 자동선택 보강

- 수동정규식에서 반복된 가나 효과음, 짧은 한자 반응과 숫자·한자·문장부호 조합을 최우측 독립 영역 또는 검증된 말풍선 안에서 범용 자동선택합니다.
- `わきゃる（分かる）`, `フ、フルネーム…`, `ほら、シャルティア` 같은 풀이·말더듬·혼합 대사가 큰 공백으로 분리되어 있으면 전체 선택합니다.
- `………　は？` 같은 말줄임표+한 글자 반응은 사방 여백이 있을 때 선택하고 AA에 밀착된 경우는 제외합니다.
- `╋━━╋`와 `┃ … ┃`로 닫힌 상태창 안의 일본어 라벨과 값을 자동선택하며 테두리와 숫자만 있는 부분은 그대로 둡니다.
- 반복 한자·반각 가타카나 질감과 눈썹·눈꺼풀 AA 억제를 유지하고 비례 글꼴 폭으로 인한 독립 대사 누락을 보정했습니다.
- 한 글자 수동정규식은 실제 오른쪽 줄 끝을 열린 여백으로 처리하되 나머지 2칸 여백 조건은 유지합니다.

### 1.11.6 (2026-08-09) — 문맥 기반 AA 감지와 실행 안정화

- 실험적으로 추가했던 **학습형 수동정규식**은 등록 사례의 과도한 일반화로 대형 파일의 렉과 AA 오선택을 늘려 제거했습니다. 이전 학습 프로필은 폐기하고 정확 문자열 규칙만 유지합니다.
- 학습 결과 재계산 대신 말풍선 닫힘, 실제 글꼴 폭, 상하좌우 여백과 주변 AA 연결 밀도를 직접 검사하는 문맥 감지로 교체했습니다.
- 짧은 감탄사·장음 대사·띄어 쓴 필살기·자유형 말풍선은 보호하고 눈썹·눈꺼풀·문자 질감 AA는 더 엄격하게 제외합니다.
- 한 글자 수동정규식은 좌우 표시 폭 2칸과 위아래 2줄이 모두 비어 있을 때만 적용합니다.
- Saitamaar 표시 폭으로 AA 열과 번역 폭을 보정해 화면·저장 파일의 위치 차이를 줄였습니다.
- Windows 서버 창을 숨기고 마지막 번역기 탭을 닫으면 서버도 종료하며, 이미지 내보내기는 필요할 때만 불러옵니다.

### 1.11.5 (2026-08-08) — 수동정규식 선택 우선순위 보정

- 자동 감지는 됐지만 **전체 선택**에서 빠지던 항목도 수동정규식으로 지정하면 선택됩니다.
- 이미 전체 문장으로 자동 인식된 대사는 내부의 `あ` 같은 한 글자 규칙 때문에 여러 항목으로 다시 분리되지 않습니다.
- 서로 다른 폭의 공백과 공백 사이 장식용 점, 띄어진 느낌표가 섞인 필살기 대사도 처음부터 끝까지 한 문장으로 선택합니다.
- 금지하기로 등록한 원문은 기존처럼 수동정규식보다 우선합니다.

### 1.11.4 (2026-08-08) — 수동 덮어쓰기 완전 병합

- **수동** 박스로 여러 자동선택·수동정규식 조각을 감싸면 같은 행의 공백까지 포함해 하나의 주황색 번역 항목으로 합칩니다.
- 이전 선택 색상이나 감지 방식이 일부 남지 않으며 사용자가 마지막으로 그린 수동 박스를 우선합니다.
- 줄바꿈을 넘어서 다른 행의 대사를 합치지 않아 원본 배치를 보존합니다.
- **세로수동**도 기존 조각을 새 세로 그룹 하나로 교체하고 일본어에 붙은 영문·반각 문장부호까지 함께 번역합니다.

### 1.11.3 (2026-08-08) — 수동 방향 우선과 띄어쓰기 대사 인식

- 수동정규식으로 표시된 항목도 **수동** 또는 **세로수동** 박스로 방향을 다시 지정할 수 있습니다.
- 사용자가 마지막으로 지정한 가로·세로 방향이 자동 감지와 수동정규식보다 우선합니다.
- `雷　龍　波　あ　あ…っ！！`처럼 한 칸씩 띄운 실제 대사는 공백을 포함한 한 문장으로 자동 선택합니다.
- 일정한 간격만으로 판단하지 않고 말풍선 경계와 문장성을 함께 확인해 AA 구조 행과 구분합니다.

### 1.11.2 (2026-08-08) — 2차원 AA 그림 문맥 감지

- `二·ニ·ﾆ·一·ー` 사이에 선과 점이 섞인 반복 AA 가로획을 미리 제외합니다.
- 서로 다른 한자로 보이더라도 구조 문자 비율이 높은 세로열은 대사로 인식하지 않습니다.
- 후보에 직접 연결된 AA 덩어리와 주변 2차원 밀도를 검사해 한쪽으로 이어진 그림 조각도 억제합니다.
- 반복 한자와 장문의 반각 가타카나로 그림의 명암을 채운 문자 질감 AA도 주변 연결성을 확인해 제외합니다.
- 반각 가타카나 문장 자체는 차단하지 않아 그림과 떨어진 실제 대사는 계속 선택합니다.
- 자동 감지 방향이 틀리면 **세로수동**으로 가로→세로, **수동**으로 세로→가로를 덮어쓸 수 있습니다.
- 닫힌 말풍선과 큰 공백으로 분리된 짧은 실제 대사는 보호하고, 애매한 항목만 전체 선택에서 보류합니다.
- 장음이 반복되고 단어 사이에 전각 공백이 있는 대사도 그림 선으로 오인하지 않고 문장 전체를 선택합니다.
- 금지·수동정규식 학습은 원문과 함께 주변 그림 배치도 비교합니다.
- `ニート` 같은 실제 단어와 정상 대사는 기존처럼 자동 선택합니다.

### 1.11.1 (2026-08-08) — AA 내부 세로열·짧은 대사 감지 보정

- 캐릭터 내부의 멀리 떨어진 파이프와 복잡한 특수문자 사이를 세로 대사로 연결하지 않습니다.
- 자동 세로쓰기는 행을 건너뛰지 않는 연속 열과 기호가 적은 실제 문자 슬롯을 요구합니다.
- `狂ってる…`처럼 문장성이 분명한 단문은 특이한 말풍선에서도 전체 선택에 포함합니다.

### 1.11 (2026-08-08) — GitHub 자동 업데이트

- 상단의 버전 버튼이 현재 설치본과 GitHub 최신 버전을 자동으로 비교합니다.
- 새 버전이 있으면 앱 안에서 내려받아 설치하고 서버까지 자동으로 다시 시작합니다.
- 적용 전 임시 폴더에서 의존성 설치와 빌드를 검증하며 `.env`와 사용자 규칙은 유지합니다.
- 직접 수정 중인 Git 작업 폴더는 안전을 위해 자동으로 덮어쓰지 않습니다.

### 1.10 (2026-08-08) — 문자·세로쓰기 자동 감지 정밀화

- AA 문자표에 잘못 섞인 한글과 근거 없는 음차 문자를 제거했습니다.
- 얼굴의 눈썹·눈·윤곽에 쓰이는 짧은 일본어 모양 문자는 주변 여백과 실제 어휘 증거를 함께 확인합니다.
- 세로쓰기는 양쪽 말풍선 경계가 있고 좌우 흔들림이 제한된 연속 열만 기본 자동 인식합니다.
- 금지항목의 짧은 오탐 패턴은 유사 후보를 억제하고 수동정규식은 실제 대사의 과잉 억제를 막습니다.
- 장문의 자연스러운 일본어는 위아래로 붙어 있어도 계속 자동 선택합니다.

### 1.9 (2026-08-08) — Codex 로그인·OpenRouter 번역 엔진 추가

- ChatGPT 계정으로 로그인한 Codex CLI를 통해 `gpt-5.6-luna` 번역을 사용할 수 있습니다.
- OpenRouter 개인 키로 `google/gemma-3-27b-it` 번역을 사용할 수 있습니다.
- Codex 인증 파일은 앱이 읽지 않고, OpenRouter 키는 현재 브라우저 탭에만 보관합니다.
- 기존 AA 표기 방식과 현재 Gemini 모델·호출 방식은 그대로 유지했습니다.

### 1.8 (2026-08-06) — 수동 정규식 오선택과 짧은 번역 배치 개선

- 수동 정규식은 원문의 좌우가 공백으로 분리된 경우에만 자동 선택하며, 한 글자 규칙은 위아래 2줄과 좌우 표시 폭 2칸까지 모두 비어 있어야 합니다.
- 같은 글자가 다른 단어나 AA 문자에 붙어 있을 때 생기던 과잉 선택을 막았습니다.
- 번역문이 원문보다 짧으면 부족한 표시 폭만큼 공백을 채워 뒤쪽 AA가 앞으로 당겨지지 않게 했습니다.
- 수동 번역에도 동일한 표시 폭 보존 방식을 적용했습니다.

### 1.7 (2026-08-02) — 화이트 모드와 반복 원문 자동 선택

- 상단 버튼으로 다크·화이트 작업 화면을 즉시 전환하며 선택을 다음 실행에도 유지합니다.
- **수동정규식**으로 박스 지정한 원문과 같은 문자열을 현재 파일과 이후 파일에서 자동 선택합니다.
- **수동정규식 관리**에서 규칙 삭제, 전체 삭제와 JSON 백업·복원을 지원합니다.
- 이미지 ZIP 내보내기의 캔버스 재사용과 안전한 2페이지 병렬 인코딩으로 대용량 저장 속도를 개선했습니다.

### 1.6 (2026-08-02) — 반복 오인식 금지 목록 추가

- 완전히 같은 원문이 반복되면 현재 파일에서 함께 해제되고 이후 파일의 전체 선택에서도 자동 제외됩니다.
- 상단의 **금지항목 관리**에서 잘못 등록한 항목을 삭제하거나 목록을 JSON으로 백업·복원할 수 있습니다.
